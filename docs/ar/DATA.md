# البيانات والاستيراد

## مصدر البيانات الأساسي

أصبح للنظام مصدر واحد للبيانات:

```text
public/admission-minimums.pdf
```

نفس ملف PDF متاح للتحميل داخل الموقع ويُستخدم أيضًا أثناء البناء لاستخراج البيانات. لم تعد ملفات TXT الخاصة بكل صفحة جزءًا من مسار البيانات.

## توليد JSON

شغّل:

```bash
bun run data:import
```

يستخدم السكربت إحداثيات النص من PDF.js لاكتشاف جدول القبول، وتجميع الأسطر المرئية، وتوحيد الأرقام العربية والفارسية، والتحقق من كل سجل، ثم يولّد:

```text
src/features/admissions/data/admissions.json
src/features/admissions/data/admission-import-report.json
```

يحتوي `admissions.json` على Objects واضحة بدل المصفوفات القديمة المعتمدة على ترتيب الحقول:

```json
{
  "sourceId": "103",
  "code": "287",
  "name": "جامعة بغداد / كلية الهندسة - قسم الحاسوب",
  "degreeAll": 668,
  "percent": 95.43,
  "type": "علمي",
  "sex": "مختلط"
}
```

لا تعدّل الملفات المولّدة يدويًا.

## استيراد PDF آخر

الأمر الافتراضي يقرأ `public/admission-minimums.pdf`. ويمكن تجربة ملف متوافق آخر مباشرة:

```bash
bun scripts/import-admissions.ts "./path/to/minimums.pdf"
```

يتجاوز السكربت صفحات الغلاف والصفحات التي لا تحتوي جدول القبول تلقائيًا، ويسجل أرقام الصفحات وعدد السجلات لكل صفحة داخل تقرير الاستيراد.

## التحقق والأسطر المرفوضة

الاستيراد الاعتيادي Strict ويفشل إذا:

- لم يتم استخراج أي سجل؛
- كان حقل مطلوب مفقودًا أو قيمة رقمية غير صالحة؛
- ظهرت معرفات مكررة؛
- بدا السطر كسجل قبول لكن تعذر تحليله.

تُحفظ الأسطر المرفوضة في:

```text
src/features/admissions/data/admission-import-rejected.json
```

ويحتوي الملف على رقم صفحة PDF ورقم صفحة الجدول وإحداثي Y والنص الخام للأعمدة لتسهيل تشخيص أي تغيير في تنسيق PDF. عند نجاح الاستيراد بدون أخطاء يُحذف ملف الرفض تلقائيًا.

أثناء تكييف المحلل مع PDF بتنسيق جديد يمكن مؤقتًا استخدام:

```bash
bun scripts/import-admissions.ts "./path/to/minimums.pdf" --allow-rejected
```

لا تستخدم `--allow-rejected` لبيانات الإنتاج قبل مراجعة جميع الأسطر المرفوضة.

## الفلاتر الديناميكية

خيارات الفرع والجنس تأتي مباشرة من البيانات المولدة، لذلك تظهر القيم الموجودة فعليًا في الملف فقط.
