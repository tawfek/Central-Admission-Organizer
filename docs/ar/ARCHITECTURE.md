# المعمارية

## الفكرة الأساسية

واجهة المستخدم لا تعتمد مباشرة على مصدر البيانات. توجد طبقة Repository بين البيانات والواجهة:

```text
ملفات TXT → سكربت الاستيراد → JSON مولّد → Repository → TanStack Query → الواجهة
```

## المجلدات الرئيسية

- `src/app`: المزودات، الثيم، حالة الاختيارات، والراوتر.
- `src/i18n`: الترجمات العربية والإنجليزية وإدارة اتجاه الصفحة.
- `src/features/admissions/domain`: التطبيع، الفلترة، التسميات، وقواعد الاختيار.
- `src/features/admissions/data`: JSON المولد، Repository المحلي، وTanStack Query.
- `src/features/admissions/components`: واجهة الفلاتر والنتائج المتجاوبة.
- `src/features/selection`: السحب والإفلات، المدن والمحافظات، الترتيب، المشاركة، والطباعة.
- `src/components/ui`: مكونات shadcn/Radix المملوكة للمشروع.

## ترتيب المدن

الترتيب حسب المدينة يعمل كـ stable partition: الاختيارات المطابقة تنتقل إلى الأعلى مع الحفاظ على ترتيبها الحالي، ثم تأتي بقية الاختيارات مع الحفاظ على ترتيبها أيضًا. بعد ذلك يبقى السحب والإفلات فعالًا بصورة طبيعية.

## الباك إند

لا يوجد باك إند مطلوب أثناء تشغيل الموقع. Vite يضمّن `admissions.raw.json` داخل البناء. مستقبلاً يمكن استبدال Repository المحلي بواجهة API من دون إعادة كتابة الشاشات.


## حالة الاختيارات والحفظ

الاختيارات وترتيبها هي حالة خاصة بالتطبيق وليست Server State. تبقى بيانات الأقسام داخل TanStack Query، بينما يحتفظ Selection Provider بحالة مبنية على المعرّفات فقط داخل `localStorage` وبنسخة Version واضحة.

الحالة المحفوظة تتضمن:

- معرّفات الأقسام المختارة؛
- تسلسل الاختيار الأصلي؛
- الترتيب الحالي؛
- وهل قام المستخدم بإنشاء ترتيب مخصص.

عند الرجوع إلى الصفحة الأولى وإضافة أو حذف أقسام، لا تتم إعادة بناء الترتيب. الأقسام التي ما زالت مختارة تحتفظ بترتيبها، والأقسام المحذوفة تزال فقط، والاختيارات الجديدة تضاف إلى نهاية القائمة. زر إعادة الترتيب يعيد تسلسل الاختيار الأصلي، وعمليات الترتيب الجماعي تحتفظ بخطوة تراجع واحدة في الذاكرة.

يتم الاعتماد على `sourceId` الثابت بدل رقم الصف. وعند تحميل مجموعة بيانات جديدة، تزال تلقائياً المعرّفات القديمة التي لم تعد موجودة حتى لا تسبب بيانات `localStorage` القديمة أي مشكلة.
